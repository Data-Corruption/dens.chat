The Relay spike: your part
==========================

Everything is in C:\Users\datac\dens-vm\relay, which the guests see as
/mnt/hgfs/dens-vm/relay. Every run writes its log into logs\ there, and I
read them from here: nothing needs pasting back, only what you saw or heard
where a step asks.

Windows is at 10.0.0.43 and is always side a. Each guest prints its own
address when a run starts ("This guest is at 10.0.0.57"). FEDORA and NIXOS
in a step stand for those addresses: type the numbers, not the word.

The guests must be bridged onto the LAN, so they have 10.0.0.x addresses:
VMware's VM menu > Settings > Network Adapter > Bridged. A guest at
192.168.x.x is still on VMware's NAT.

Windows commands go in an ordinary PowerShell in C:\Users\datac\dens-vm\relay.
The ones marked ELEVATED go in an administrator's PowerShell, same folder.
Guest commands go in a terminal:
    sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other    (if it isn't mounted)
    cd /mnt/hgfs/dens-vm/relay


A. Capture, each machine alone (4 minutes each)
-----------------------------------------------

A1. Windows. Play music or a video, and leave it playing.
        powershell -ExecutionPolicy Bypass -File .\capture.ps1
    The sound mutes and drops to 0 by itself during the first 70 seconds.
    Then it asks five things of you, each as its moment comes: another
    output as the default, and back; the output unplugged, and back; the
    music paused.

A2. Fedora GNOME, then A3. Fedora KDE:
        ./guest.sh info
        ./guest.sh capture
    It plays its own tone and runs itself for two minutes. Then it asks you
    to disconnect the VM's sound card (VMware's VM menu > Removable Devices >
    Sound Card > Disconnect), and 25 seconds later to connect it again.

A4. NixOS GNOME:
        ./guest.sh info
        ./guest.sh capture
        ./guest.sh flatpak-capture
    The same, from the session and then from inside Dens's Flatpak. Each asks
    for the sound card once.


B. The link (2 minutes each)
----------------------------

Start the guest's side first, then Windows', within a minute.

B1. Windows' desktop session with Fedora GNOME's.
    Guest:    ./guest.sh link 10.0.0.43
    Windows:  powershell -ExecutionPolicy Bypass -File .\link.ps1 -Peer FEDORA
    With sound playing on Windows, press and hold F8 for a second, a few
    times. If Windows asks about the firewall, tell me what it says, and
    click Allow.

B2. Windows as a service with Fedora under the service's sandbox.
    Guest:    ./guest.sh sandbox 10.0.0.43          (asks for sudo)
    Windows, ELEVATED:
              powershell -ExecutionPolicy Bypass -File .\service.ps1 -Peer FEDORA
    Then both again, Windows with the firewall rule Dens's installer would add:
    Guest:    ./guest.sh sandbox 10.0.0.43
    Windows, ELEVATED:
              powershell -ExecutionPolicy Bypass -File .\service.ps1 -Peer FEDORA -WithRule

B3. The same with firewalld closed, as a server's is: Fedora Workstation's
    own zone lets every high port in, so this is the one that tests it.
    Guest:    ./guest.sh firewall public
              ./guest.sh link 10.0.0.43
    Windows, ELEVATED:
              powershell -ExecutionPolicy Bypass -File .\service.ps1 -Peer FEDORA
    Guest:    ./guest.sh firewall back

B4. Windows as a service with NixOS, inside the Flatpak.
    Guest:    ./guest.sh flatpak-link 10.0.0.43
    Windows, ELEVATED:
              powershell -ExecutionPolicy Bypass -File .\service.ps1 -Peer NIXOS

B5. Fedora GNOME with NixOS, no Windows. Start both within a minute.
    Fedora:   ./guest.sh link NIXOS a
    NixOS:    ./guest.sh flatpak-link FEDORA b


C. An hour of sound, Windows to Fedora GNOME
--------------------------------------------

    Guest:    ./guest.sh hour 10.0.0.43
              A browser opens the player: click "Play what arrives".
    Windows:  powershell -ExecutionPolicy Bypass -File .\link.ps1 -Peer FEDORA -For 1h -Page -Name hour

    Use Windows as you would for the hour, with sound playing most of it. You
    won't hear the guest: what it plays goes to an output that leads nowhere,
    so Windows never hears itself. Along the way, in the guest:
      - after about 10 minutes, open a new tab in front of the player's;
      - after about 30 minutes, minimize the browser.
    In the last five minutes, stop the music on Windows, open
    http://127.0.0.1:47880/click.html in a browser there and click Start
    clicking. Leave it clicking to the end.


D. The phone (with me)
----------------------

Take the S24 off its charger, turn Wireless debugging on, and tell me the
address and port it shows. I install the build and start it; you hold the
phone, listen, and switch headphones as I ask. It takes about an hour and a
half, most of it the phone lying with its screen off.


E. The Flatpak gaining a permission (NixOS GNOME, 10 minutes)
-------------------------------------------------------------

This puts a test build of Dens in the guest, v1.12.0-relay.1, in place of
whatever Dens it has: its data stays, but a released Dens won't open that
data afterwards, so use a guest whose Dens you don't mind setting up again.

E1. Out with the Dens that's there, and its remote:
        flatpak uninstall -y chat.dens.Dens
        flatpak remote-delete dens          (flatpak remotes shows its name, if it isn't dens)
E2. In a second terminal, leave this running:
        sh /mnt/hgfs/dens-vm/relay/flatpak-1/serve.sh
E3. Install the first build, and open Dens once:
        flatpak install -y http://localhost:8080/flatpak/chat.dens.Dens.flatpakref
        flatpak run chat.dens.Dens
E4. In the second terminal, Ctrl+C, then serve the second build, which asks
    for the sound socket:
        sh /mnt/hgfs/dens-vm/relay/flatpak-2/serve.sh
E5. Three ways to the update. Tell me what each shows about permissions.
      - The command line:   flatpak update chat.dens.Dens     and answer n
      - GNOME Software: its Updates tab, Dens's row. Look, don't update.
      - Dens's own page: wait for its notice of the update, restarting Dens
        if none shows in a couple of minutes, and click Install. Say what Dens and the desktop
        each ask, and go through with it.
E6. Afterwards:
        flatpak info --show-permissions chat.dens.Dens


F. The KVM
----------

Send kvm\relay-kvm.zip to your friend. Its README.txt has their steps: four
